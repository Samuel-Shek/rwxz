# 公众号长文与爆文工具箱

写公众号长文、爆文、需要强开头的长帖时读本文件。内容来自 rwxz v2 的实战积累（早期写作复盘），面向中文社交媒体长文。英文长帖可以借用钩子和结构思路，但例句、写手参照和平台规则是中文语境的，不要直接照搬。

这里的每一种钩子、动作、收尾都是可选项。挑最适合素材的一种；素材撑不起就不用，直接从最有信息量的事实开始。

## 1. 爆文的底线：信任先于刺激

爆文不是把话说满，而是让读者觉得“这个人真懂，而且没有骗我”。

- 先讲真实问题，再讲方案。
- 先给具体信息，再给抽象判断。
- 先承认边界，再表达立场。
- 结论可以有力，但不能靠编造案例、数据、身份、收益或保证撑场面。

## 2. 选题强度：HKR

- `H` 好奇心：读者有没有点开的理由？
- `K` 知识量：看完有没有得到新东西？
- `R` 共鸣感：有没有戳中真实的困惑、欲望或焦虑？

至少命中两项。只剩情绪、没有信息量时，先补素材或换角度。

## 3. 提炼爆点

先把文章压成一句话：这篇要让什么读者，因为看见什么事实，改变什么判断，最后做什么？

再从下面选一个主爆点：

- 反差：大家以为 A，其实关键在 B。
- 痛点：读者一直卡在一个具体问题上。
- 真相：行业里常被省略的一层工作。
- 体验：我 / 我们真实做了一遍，发现不一样（必须是用户提供的真实经历）。
- 选择：读者要在几个方案里做取舍。
- 入门：把复杂概念讲到普通人能懂。
- 转化：为什么这个服务不是随手用 AI 糊出来的。

## 4. 开篇钩子

| 类型 | 适用场景 | 示例 |
|---|---|---|
| 反差事实 | 有可核验的反差 | 从实际核实的两种结果对比开始，保留条件 |
| 故事切入 | 用户提供了真实经历 | 从用户给出的具体场景开始，时间和动作不补写 |
| 悬念问句 | 读者已有好奇 | “同一套方法，为什么换个场景就失效？” |
| 反直觉断言 | 有足够证据支持 | 先给有依据的判断，再说明适用条件 |
| 个人踩坑 | 有用户本人提供的经历 | 保留用户自己的发现和修正，不编第一人称体验 |

示例只演示结构，不是历史或经历材料；实际写作须核对事实。

不用的开头：在当今时代、随着技术发展、说到 X 相信大家都不陌生、众所周知。

## 5. 中段的洞察感动作

| 动作 | 怎么用 |
|---|---|
| 文化参照物嫁接 | 把题材接到读者熟悉的另一个领域（流程 → 菜谱、路线、检查表） |
| 时间纵深 | 把人物或概念串成一条几百到几千年的线（早期方法 → 新工具 → 当前用法） |
| 反向追问 | 不问“X 是什么”，问“为什么 X 是 8 个，不是 6 个也不是 16 个” |
| 拆解错位 | 不列表对比，讲一个场景下的功能差（计划与执行的区别） |
| 事实压阵 | 直接给一个时间、数字或历史事实（须核实） |

## 6. 类比

老套比喻尽量不用：骨架、地图、地基、引擎、灯塔、罗盘、桥梁、钥匙。

更新鲜的方向：

- 操作系统层 vs 应用层（基础能力与具体工具）
- 元素周期表 vs 化学反应方程式
- 经纬度坐标系 vs 导航路线
- 字母表 vs 一句完整的话
- 源代码 vs 运行中的进程
- 建筑蓝图 vs 已建成的小区
- DNA 序列 vs 长出来的人

类比要让读者今天就用得上，并且只在它真的帮助理解时用。

## 7. 节奏

- 关键论点可以独立成段，制造重点；但不要连续四段以上一句一段。
- 长句负责递进推理，短句负责落锤定调，长短交替。
- 口语语域的长文，走神的地方可以用一句口语转折把读者拉回来（“说回正题”“你想想看”）。不定额，同一个说法全文不重复。
- 讲完故事或旁支，要有一句把读者拉回主线：“我提 X，不是为了 Y，而是想说 Z”。
- 不用纯 bullet 代替叙述。只有需要并列、需要扫读的地方才用列表。

## 8. 收尾

| 类型 | 怎么用 | 示例 |
|---|---|---|
| 哲思留白 | 短句独立成段，不解释 | 用短句收住已经论证过的判断 |
| 回环呼应 | 回到开头的具体场景，但视角已经变了 | 结尾回到开头那个具体场景 |
| 反讽尾刀 | 一句话把全文翻面 | 让读者重新理解开头的同一件事 |
| 行动召唤 | 给一个具体的小动作，不是“点赞” | 给出读者下一次遇到该问题时能做的一步 |
| 信念宣言 | 对一个长期判断的坚定表达 | “它不替你做决定。但能在做决定之前，把局面看清一点。” |

## 9. 公众号长文的常见结构

1. 一句话前提（写给自己，不一定放进正文）
2. 开篇钩子
3. 主体 3–5 节，每节只承担一个结论
4. 证据：测试、案例、过程、对比或明确推理
5. 适合谁、不适合谁（有转化目的时）
6. 价格、服务或下一步（用户提供了才写）
7. 收尾
8. CTA 与相关文章链接（有才放）

交付件（标题备选、推荐标题、发布前检查）见 `channels.md` 的公众号一节。

## 10. 可复用的表达锚点

可以用，但全文最多一两句，不堆：

- “真正值钱的，不是最后那一段文字，而是中间那层看不见的判断。”
- “你缺的也许不是一个标准答案，而是一个更清楚看见问题的角度。”
- “它不替你做决定，但能帮你把决定前该看清的东西先看清一点。”
- “如果只看表面，这件事很像 A；但真正影响结果的，其实是 B。”

“不是……而是……”句式本身容易变成套路，一篇里用一次就够。

## 11. 借鉴的写手动作

- 科技与人文叙述（科技 + 人文）：用第一人称把读者拉进具体场景，再抽离出来评论；偏离主线后一定扣回主线；升华时接一个文化或哲学参照物，而不是空喊大词。
- 利益与幽默叙述（金融 + 黑色幽默）：别人讲意义时讲利益和钱；把行业黑话翻成大白话；写给围观群众，不写给圈内人。
- 知识型叙述（科普 + 历史）：标题常用“为什么”起手；不用教科书式开篇；硬数据多，去个人化，但结尾留一刀。
- 生活型叙述（杂文 + 生活）：标题短；数据 → 案例 → 比喻三层递进；反讽尾句。
- 旧知识新角度叙述（讲老知识讲新意）：旧知识用新角度讲；多学科交叉；一句一个信息点。
- 历史分析叙述（历史、政治深读）：锚定关键人物 → 拆立场动机 → 推可能动作；连续剧式留扣。
- 共鸣型叙述（爆款共性）：共鸣来自反差，同一件事翻个面；新洞察比新事实更重要。

## 12. 写法维护

维护者可按需要研究有可靠出处的公开写作指南，并核对许可。方法只在实际有用时采纳，不把他人原文或用户私稿直接复制进通用素材。

可检查词汇、风格一致性、内容质量与可读性；写作事实仍须来自用户材料或可核验的一手依据。

## 13. 爆文专项检查

- 第一屏能让读者知道这篇和自己有什么关系吗？
- 有明确的主判断，而不只是堆信息吗？
- 每个强说法都有事实、体验、证据或边界吗？
- 中段有新信息、新角度或新判断吗？
- 结尾回扣了开头，或给了读者一个具体动作吗？
- 公众号正文段落够短、适合手机读吗？
- 系列稿和前几篇的结构件一致吗？
